# AXIS_FOLLOW_R4：小步上下修正与先定位再跟踪

**最新源码为AXIS_FOLLOW_R5 / VOI7，见README_AXIS_FOLLOW_R5.md。**用户确认R4效果明显改善，R5小幅增加步长，并针对已提供的valid=0与形状标签漂移增加锁定后的目标接续。下文为R4历史记录。

用户反馈R3对红色圆形仍快速上下晃动，并描述将目标放在画面中心后发f，舵机快速下转并丢失目标。本版按请求缩小上下单次修正、限制连续修正速度，并明确首次启用舵机与进入自动跟踪的区别；不据此认定实际中心坐标和反馈方向已经核验。

## 已取得的实机记录

`C:/Users/13329/Downloads/records-2026-10-23-19-10-54.json`实际包含18:27～18:31的R3启动、a/f/d记录：启动VOICE_KEY4_V5 AXIS_FOLLOW_R3、MFCC和Fabric ID自检通过。第一次f回复cfg=3、fresh=0、servo_us=1500；随后d回复servo_us=1568，再次a/f/d后为1788。文件没有p、XY或目标放在中心时的坐标记录，不能由此确认居中目标确实被控制器看到，也不能判断刚开启时转动的具体方向或幅度。

R3的f会从失能状态直接启用舵机，开始输出保存的脉宽。即使当时没有fresh目标，也可能从用户手工摆放的机械角度转到保存位置。1500us并未标定成该支架的水平角，手工摆正镜头也不会修改寄存器脉宽。本版把这个动作从f移到显式的e手动启用流程；不会声称无编码器就能获知断电后真实角度。

## 改动

- 上下每个新结果的修正：偏差>160像素由24降为6us，81～160像素由12降为4us，其余由4降为2us。
- 两次非零上下修正至少间隔80ms，控制节拍和视觉结果到达时刻可能让实际间隔更长。等待期间只保留最新结果的待修正量，不累积位移队列。上限是6us/80ms，即75us/s；这只是指令变化的上界，不是测得的舵机角速度。
- 保留R3每个新结果最多一次修正、中心40/64像素双阈值、启动/反向两帧确认、明确失效和500ms冻结帧超时处理。保留候选扫描期间的已提交结果，真正空候选或检测失败仍清掉目标。
- FD命令f在轴未启用时回复FOLLOW_NEEDS_MANUAL_POSE，不写启用寄存器。先e启用手动、确认姿态后再f；已启用时f沿用现有已发出的脉宽。e首次启用仍会输出保存的脉宽，并不保证从未知机械位置完全无动作。
- 状态新增VISION十进制x/y/valid，方便核对中心约(640,360)。它是诊断读取，不声称与前面跨多个UART行的字段构成同一瞬间的完整原子快照。
- 水平控制和±1024脉冲、舵机1000～2000us限位保留；手动j/l±32脉冲、i/k±50us保留。减幅只针对自动上下修正，不改手动步长。x/y不默认翻转，必须结合实际坐标和物理方向判断。

## 配套使用

FPGA ID为VOI6（0x564f4936），固件启动VOICE_KEY4_V6 AXIS_FOLLOW_R4；bit和ELF需要一起更新。

1. 旧程序发d，停止FD调试。TD下载 `td_project/cli_build/camera_to_dsi_display.bit`，关闭TD下载连接后用FD加载 `D:/Anlogic/FDwork/voice_key4_app/build/voice_key4.elf` 并Resume。COM11先打开，确认R4与自检通过。
2. 先发e，舵机会按保存脉宽启用。用i/k调整到合适的起始姿态；不把手动拧动角度当作程序已经知道的位置。
3. 发a选红色圆形，将目标放在画面中心并等待新结果，发p确认VISION valid=1、x约640/y约360。若坐标不符，先保留该记录排查，而不是连续f。
4. 发f进入跟踪；s保持，e返回手动，d关闭输出。若需要排查突然下转，比较开启前后VISION坐标、servo_us与active_us，区分首次启用定位和目标误差修正。

R3配套bit、ELF及本轮修改前主要源码和测试备份在 `D:/Anlogic/方案/axis_follow_r3_before_small_step_20261023`，回退时axis_follow_r3.bit和axis_follow_r3.elf配套恢复。
